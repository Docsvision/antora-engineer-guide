= Настройка временных зон

Настройка часовых поясов позволяет пользователям работать с датой и временем в своих временных зонах. По умолчанию для отображения времени система использует время сервера. После выполнения настройки все значения, включая заданные ранее, будут отображаться в часовом поясе пользователя.

.Чтобы настроить работу часовых поясов:
. Установите системные модули, требуемые для работы с часовыми поясами:
+
--
* {pl} {pl-tz-req}.
* {bo} {bo-tz-req}.
* {wc} {wc-tz-req}.
--
+
WARNING: Без модулей указанных версий работа в {wc}е будет невозможна. Все системные серверы и сервер БД должны находиться в одном часовом поясе.
+
. В БД {dv}, в таблице `dvsys_settings`, задайте настройку `TimeZoneMode`:
+
* `Off` = `0` -- поддержка часовых поясов выключена. Значение по умолчанию для новых БД.
* `ClientManual` = `1` -- поддержка часовых поясов включена. В {wc}е используется часовой пояс из справочника сотрудников.
// * `ClientAuto` = `2` - поддержка часовых поясов включена, часовой пояс определяется автоматически на уровне клиентской сессии.
+
include::dv6@system:ROOT:partial$restart-sss.adoc[]
+
. Выполните xref:6.2@mgmtconsole:servers:db-update.adoc[обновление БД] из {of-mc}, затем откройте страницу menu:Серверы[Имя сервера > {wc}], перейдите к группе настроек "xref:6.2@mgmtconsole:servers:webclient-solutions.adoc[Решения]" и импортируйте стандартные решения с разметками карточек.
+
.Поле "Часовой пояс" добавлено в следующие разметки:
* xref:GBL-2272@webclient:user:directories/staff/employee.adoc#time-zone[Разметки сотрудников].
* xref:GBL-2272@webclient:user:directories/staff/departments.adoc#time-zone[Разметки подразделений].
* xref:GBL-2272@webclient:user:directories/staff/companies.adoc#time-zone[Разметки организаций].
+
. При необходимости обновите собственные разметки {wc}а для отображения часового пояса.
+
. Нажмите кнопку *Применить* в правом верхнем углу окна {of-mc}, чтобы применить настройки {wc}а и перезапустите службу Сервера {wc}а.
+
Изменения применяются после обновления данных справочника сотрудников в кэше {wc}а и повторного входа пользователя в систему.

[#limitations]
== Ограничения

* Часовой пояс пользователя не определяется автоматически по настройкам браузера или ОС устройства.
* Все серверы {dv}, работающие с одной БД, и сервер СУБД должны использовать один часовой пояс. Менять его после начала эксплуатации БД не поддерживается.
* В собственных приложениях необходимо самостоятельно реализовать применение часового пояса пользователя. Настройка `TimeZoneMode` не включает его автоматически во всех приложениях.
* Поддерживаются часовые пояса с фиксированным смещением относительно UTC. Переходы на летнее и зимнее время не учитываются.
* Расчёт сроков по бизнес-календарю, формирование писем и уведомлений, отображение часового пояса в штампе электронной подписи не поддерживаются в рамках данной функциональности.
